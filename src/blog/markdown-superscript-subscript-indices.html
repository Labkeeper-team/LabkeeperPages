Зачем нужны индексы в текстовых документах

При подготовке научно-технических заметок, отчетов по лабораторным работам и технической документации регулярно возникает необходимость вставить степень величины ($x^2$, $10^5$), обозначить химический элемент ($H_2O$, $CO_2$) или указать номер итерации в алгоритме ($a_{i+1}$). В чистой спецификации CommonMark нет встроенного символа для таких операций, однако существует несколько надёжных подходов.

В этой статье мы подробно разберем, как органично внедрить индексы в markdown sub sup с помощью стандартных HTML-тегов, математических вставок KaTeX/MathJax и специальных расширений синтаксиса. А если вы готовите структурированные данные, рекомендуем также посмотреть наше руководство по созданию сложных таблиц в Markdown.

Индексы в Markdown sub sup: использование базовых HTML-тегов

Поскольку спецификация Markdown полностью поддерживает прозрачную вставку HTML-тегов, самый кроссплатформенный и универсальный способ проставить верхний или нижний индекс в markdown — использовать парные теги <sup> и <sub>.

Markdown
Верхний индекс (степень): x<sup>2</sup> + y<sup>2</sup> = z<sup>2</sup>
Нижний индекс (вещество): H<sub>2</sub>SO<sub>4</sub>
Комбинированный индекс: A<sub>i</sub><sup>(k)</sup>
Текстовая сноска: Данные исследования<sup>[1]</sup> подтверждены.

Результат визуализации в браузере:

  • Верхний индекс: x2 + y2 = z2
  • Нижний индекс: H2SO4
  • Комбинированный индекс: Ai(k)
  • Текстовая сноска: Данные исследования[1] подтверждены.

Этот метод работает во всех современных движках: GitHub, GitLab, Obsidian, Notion, а также в веб-редакторе при интеграции чистого HTML внутрь Markdown.

Нижний индекс в Markdown через математический блок KaTeX/MathJax

Если индекс является частью математического выражения или физической формулы, предпочтительно использовать синтаксис LaTeX-математики, обрамленный знаками доллара $...$. Для нижнего индекса служит символ подчеркивания _, а для верхнего — крышка ^.

LaTeX Math в Markdown
В строке: Скорость тела равна $v_0 = 12\text{ м/с}$, а ускорение $a = 9.8\text{ м/с}^2$.
Сложный индекс в фигурных скобках: $T_{max} = 300\text{ K}$, $x_{i,j}^{(n+1)}$.

В отдельном блоке:
$
\sum_{i=1}^{n} x_i^2 = \sigma_{total}^2
$

Важное правило: если в индексе содержится более одного символа (например, max или i+1), его обязательно нужно заключать в фигурные скобки: $x_{max}$, иначе нижним индексом станет только первый символ, а остальное останется обычным текстом ($x_max$ превратится в $x_m$ax).

Расширения Pandoc и GitHub Flavored Markdown

В академическом конвертере Pandoc и ряде специализированных редакторов поддерживается компактный сокращенный синтаксис:

  • Тильды для нижнего индекса: H~2~O превращается в H2O;
  • Крышки для верхнего индекса: x^2^ превращается в x2.

Однако помните, что на чистом GitHub или базовых парсерах CommonMark такой синтаксис не всегда активен по умолчанию. Поэтому связка <sup> / <sub> либо формульный блок $...$ остаются наиболее надежным выбором. Подобная аккуратность особенно важна при верстке резюме в Markdown, где символы должны парситься корректно любыми сканерами.

Типичные ошибки верстки индексов

Чтобы верстка выглядела аккуратно и не разрывала межстрочный интервал абзаца, обратите внимание на следующие нюансы:

  • Лишние пробелы внутри тегов: конструкция <sub> 2 </sub> может вызвать нежелательные отступы вокруг цифры. Пишите слитно: <sub>2</sub>.
  • Смещение высоты строки в браузере: в старых CSS-фреймворках теги sup и sub могут слегка увеличивать line-height строки. В редакторе Labkeeper стили нормализованы с помощью vertical-align: baseline и относительного позиционирования.
  • Кириллица в формулах: если вам нужен поясняющий русский индекс в формуле LaTeX, оборачивайте его в \text{...}: $F_{\text{тр}} = \mu N$.
