# 🚀 Labkeeper Blog Generator

Автоматизированный инструмент для мгновенной генерации SEO-оптимизированных статей блога Labkeeper на основе чистого контента (JSON) и эталонного HTML-шаблона.

---

## 📂 Структура модуля

```text
scripts/blog-generator/
├── template.html              # Эталонный HTML-шаблон статьи (метатеги, шапка, футер, CTA)
├── generate.js                # Основной движок сборки
├── articles-data/             # Папка для JSON-файлов со статьями (пачки контента)
│   └── batch-markdown.json    # Пачка 2 (актуальные статьи)
├── README.md                  # Данное руководство
├── HOW-TO-WRITE-ARTICLES.md   # Чек-лист для AI-агентов, готовый промпт и правила SEO
└── SEO-KEYWORDS-REGISTRY.md   # Реестр связок URL <-> Ключи для трекеров позиций
```

---

## ⚡ Что делает скрипт автоматически

Когда вы запускаете скрипт:
1. **Создаёт чистовые HTML-страницы**: берёт каждый объект статьи из `articles-data/*.json` и компилирует файл `src/blog/<slug>.html`.
2. **Проставляет комментарий пачки**: на 2-й строке HTML добавляет `<!-- Пачка N -->` (для удобства версионирования).
3. **Вставляет микроразметку Schema.org**: генерирует валидный JSON-LD для `Article` и `BreadcrumbList`.
4. **Вставляет метатеги и комментарии по SEO**:
   - `<!-- SEO Ключи: ... -->` в начале `<head>` для SEO-специалиста.
   - `<meta name="keywords" content="..." />` для поисковых ботов.
5. **Обновляет каталог `src/blog.html`**: добавляет новую карточку статьи в сетку `#blog-grid` с правильными тегами и ссылками (дубликаты исключены).
6. **Обновляет блок статей на главной `src/index.html`**: вставляет карточку в `.knowledge__swiper .swiper-wrapper` в чистом статичном HTML без JS (критично для быстрой индексации поисковыми роботами).
7. **Обновляет слайдер рекомендаций**: регистрирует статью в массиве `ALL_BLOG_ARTICLES` в файле `src/assets/js/slider.js` (блок «Другие статьи»).
8. **Обновляет карту сайта `src/sitemap.xml`**: автоматически запускает скрипт генерации карты сайта.

## 🛠️ Как запускать

### Примеры в редакторе и проверка статей

Для каждой статьи добавьте запись с ее `slug` в `editor-examples.js`.
Значение содержит один или несколько текстовых сегментов:

```js
'my-formula': { latex: String.raw`\[E=mc^2\]` },
'my-notes': { markdown: '# Notes\n\nA short example.' }
```

Для примеров с пакетами используйте существующий помощник `latex(body, preamble)`:
он собирает самостоятельный документ. Примеры должны быть небольшими и соответствовать
теме статьи. Данные и библиографию можно включить через `filecontents*`; внешние файлы
не должны требовать ручной загрузки. Не добавляйте в URL секреты или персональные данные.

Отдельно проверяйте зависимости среды: наличие пакета не гарантирует совместимость
с текущим TeX, а BibLaTeX требует запуска Biber и разрешенных ссылок в готовом PDF.
В коротком примере статьи о Biber используется `thebibliography`, а в примерах ЕСКД
рамка нарисована через TikZ. Эти упрощения прямо пояснены в соответствующих статьях.

Генератор создает обе ссылки `/project/default` с параметрами `latex`, `markdown`,
`compute`, `open` и `example=1`, безопасно кодирует их и проверяет длину полного URL, включая
`https://labkeeper.io`. Лимит 2000 символов является консервативным бюджетом проекта,
а не универсальным ограничением браузеров. Слишком длинный или отсутствующий пример
останавливает сборку до записи страниц. Не сокращайте готовый URL обрезанием строки.

Параметр `example=1` требует соответствующей поддержки в LabkeeperEditor:
пример открывается во временном документе, не дописывается в гостевой черновик
и не меняет личные проекты. Правки примера не сохраняются; редактор показывает
уведомление и ссылку для возврата к своей работе. Сначала разверните поддержку
этого режима в редакторе, затем публикуйте новые ссылки блога.

Формулы в тексте отрисовываются локальной копией KaTeX. Файлы из зафиксированной
npm-зависимости, включая лицензию и шрифты, копируются в `src/assets/vendor/katex`
при генерации. CDN и изменение CSP не требуются. Блоки `<code>` и `<pre>` сохраняют
исходный синтаксис и не обрабатываются как формулы. Используйте `$...$`, `$$...$$`,
`\(...\)` или `\[...\]`; буквальный HTML в примерах экранируйте.

Полная генерация также обновляет кнопки, ресурсы и обертки таблиц в старых статьях,
не имеющих JSON-источника. Остальное содержимое этих страниц сохраняется.

```bash
npm ci
npm run blog:generate
npm run blog:check
npm test
npm run lint
npx playwright install chromium firefox webkit
npm run test:blog
```

`blog:check` ничего не записывает и проверяет актуальность HTML. Unit-тесты проверяют
ссылки, экранирование, метаданные, сохранность примеров и повторную генерацию.
Браузерные тесты запускают локальный HTTPS-сервер (для временного сертификата нужен
OpenSSL; сертификат не сохраняется в репозитории): проверяют все статьи в Chromium,
Firefox, WebKit и мобильных профилях Android/iPhone, переключение языка,
формулы и отсутствие горизонтального переполнения. Они не запускают компиляцию
на production. Измененные примеры дополнительно проверяйте через интерфейс целевого
редактора с поддержкой query-параметров.

Skill для этого процесса: `.agents/skills/blog-article/SKILL.md`.

### Вариант 1. Через npm-скрипт (рекомендуется)
```bash
npm run blog:generate
```

### Вариант 2. Напрямую через Node.js
```bash
node scripts/blog-generator/generate.js
```

### Вариант 3. Обработать конкретный JSON-файл пачки
```bash
node scripts/blog-generator/generate.js scripts/blog-generator/articles-data/batch-markdown.json
```

## 📋 Поддерживаемые категории (slug и название)

В поле `categories` можно указывать один или несколько идентификаторов:
- `latex` — Работа с LaTeX
- `markdown` — Работа с Markdown
- `labs` — Лабораторные работы
- `diploma` — Дипломные работы
- `cv` — Оформление резюме / CV
- `articles` — Оформление научных статей
